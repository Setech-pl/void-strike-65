# Independent audit — Void Strike 65, October 2026

Audited `main`, commit `1a3c8bf3d637691d3f2bc6ebfe36d9bb6b11466c`, on 2026-10-06. Read-only review; no production fixes or tracked-file edits. The rebuilt default ATR is SHA-256 `e0aa70620e1ae07449410521c65eade0a8cd77254a78a44a140743dc348f41a1`, matching the committed evidence.

## 1. Summary — five most important findings

1. **AUD-01, S2:** the save-write guard checks a directory in RAM, so swapping D1: can make the game overwrite sector 599 of an unrelated writable disk.
2. **AUD-02, S2:** runtime overlays lack content integrity checks; one changed boss-table bit produces a module count of 29 and writes beyond the 16-module arrays.
3. **AUD-03, S2:** the boss DLI performs binary scroll arithmetic without clearing decimal mode; an injected NMI with D set produces the wrong HSCROL value.
4. **AUD-04, S3:** the boss stress test puts all five shots into one column; distinct-module kills exceed its 7,000-cycle bound in additional harness probes.
5. **AUD-05, S3:** the recorded preview failure now stops at a stale colour pin before its behavioural assertions, repeating the failure pattern the previous review sought to eliminate.

Two additional findings cover the PAL audit's acceptance rules and stale domain documentation. **No S1 defect was established; no fresh native emulator replay was run.** The S2 findings have concrete code/harness evidence, but their rare triggering conditions were not reproduced on a real Atari. Cycle probes below measure linked NMOS 6502 instructions with the repository harness, not ANTIC DMA or physical PAL timing.

## 3. Findings

### AUD-01 — the save guard cannot distinguish the boot disk from another disk

**What.** The writer compares the save sector/count against `overlay_directory`, which is already resident in RAM. It does not read a disk identity before sending PUT. Invalid save-sector contents are converted to an empty record, allowing a subsequent best-score improvement to write it back.

**Evidence.** `src/hybrid/level-summary.s:656`:

```asm
@directory:
        lda overlay_directory + SAVE_RECORD_ENTRY * 5,x
        cmp save_record_entry,x
        bne @refused
```

At `:549-575`, missing magic, version or checksum takes `@empty` and constructs a new RAM record. At `:194-195`, the level-end path calls that read and then `summary_update_record`; the latter reaches `summary_write_save` at `:620`. The writer sends `SIO_CMD_PUT` at `:679-680`. None of these steps identifies the media currently in D1:.

**Reproduction / execution path.** Boot the valid ATR, finish a boss, and substitute an unrelated writable disk after the summary art read but before the save read/write. A readable foreign sector 599 without `VR` is treated as empty; the newly earned grade/score is then written to that sector. The in-memory directory still matches.

I also called the linked `summary_write_save` using `bossGateMemory()`, the harness `Drive`, and hooks recording the command frame. With no media-identity response at all, the routine emitted `[49, 80, 87, 2, 218]`: D1:, PUT, sector `$0257` = 599, checksum `$DA`. This probe timed out at ACK and made **no physical disk write**. It confirms that the command is issued before any media validation; the foreign-disk overwrite itself remains an execution-path inference.

**Why it matters.** A fixed sector protects the game's own image layout, but that same sector can contain unrelated data on a replacement disk. Read-back verification happens after the damaging write.

**Smallest fix.** Before persistence, verify a stable identity stored on the mounted image. On mismatch or failed identity read, keep the in-memory result and silently skip persistence. Keep the fixed-sector check too. An invalid record may still display as empty without authorizing a write to unidentified media.

**Test that catches it.** Extend the existing writable Drive fixture to swap to a foreign image immediately before the record read. Give its sector 599 distinctive non-`VR` bytes. Assert zero PUT commands and byte-exact preservation of that sector. The current code would issue PUT.

### AUD-02 — runtime overlays accept corrupt content and the boss count is unchecked

**What.** Boot DFMC chunks receive CRC16 validation. The later overlay path only checks the SIO wire checksum. A drive computes that checksum over whatever bytes are on the disk, including damaged or wrong-image bytes. The boss executes loaded code and consumes loaded tables without a corresponding content CRC or module-count bound.

**Evidence.** `src/hybrid/boss.s:249-251`:

```asm
    jsr sector_reader_read_sectors
    bcs @failed
    rts
```

After the runs, `boss_head` jumps to `boss_install` at `:234`. `src/hybrid/sector-reader.s:690-696` compares only `sr_checksum` with the received checksum. `src/c/boss.c:236,252`:

```c
    boss_count = TABLE[BOSS_T_MODULE_COUNT];
    /* ... */
    for (boss_n = 0u; boss_n != boss_count; ++boss_n) {
```

The HP, stage, kind and hidden arrays each have 16 entries. The asset converter bounds authored module counts (`scripts/boss-assets.mjs:343`), but that check occurs before disk storage and loading.

**Reproduction.** In a copy of `runBossEntry().memory`, change the shipped table byte at `$AD00 + BOSS_TABLE.moduleCount` with XOR `$10`. The count changes from 13 to 29. Calling the linked `_boss_c_init` returns with `_boss_count = 29`. A write hook observed stores at `$1765-$1771`, beyond `_boss_hp`'s legal `$1755-$1764` range, overwriting adjacent controller state. This is a one-bit change to the actual region-1 table, not a fabricated oversized asset. No disk or tracked file was changed.

**Why it matters.** A cleanly delivered damaged sector can corrupt gameplay state; damaged executable overlay bytes can instead jump or hang. The robust boot CRC contract does not extend to the transition loader. The current pristine image is not alleged to contain such corruption.

**Smallest fix.** Immediately reject a module count outside 1..16 before controller initialization. Add expected content checksums for executable/data overlay runs, held in validated resident metadata, and check them before executing/consuming the runs. Bounds checking closes this specific overwrite; checksums cover the broader overlay failure.

**Test that catches it.** Have the Drive return an otherwise correct band-B sector with this bit changed and recompute the SIO checksum normally. Assert a failure-screen transition before controller initialization and no stores outside the declared arrays. Also corrupt a byte in the summary or boss executable run and require refusal before execution.

### AUD-03 — boss DLI arithmetic inherits the interrupted decimal flag

**What.** The boss DLI preserves A and, when needed, X, but does not execute CLD before calling `boss_apply_pos`. On NMOS 6502, NMI preserves rather than clears D. Mainline boss scoring explicitly uses SED (`src/hybrid/boss.s:582-590`), so D is not globally guaranteed clear during an interrupt.

**Evidence.** `src/hybrid/boss.s:330-339`:

```asm
    clc
    adc #15
    and #$F0
    ; ...
    sbc boss_shown_pos
```

The second DLI reaches this routine at `:317` when the published position differs. There is no CLD in `boss_dli:278-324`. `tests/boss-harness.mjs`'s `nmi()` helper starts with the CPU's normal binary flags; the existing motion/DLI tests do not test D=1.

**Reproduction.** Use the linked boss entry image, phase 1, `boss_shown_pos = 0`, `boss_shown_lms = 0`, and `boss_dli_pos = 14`. Push a simulated NMI return frame and run `boss_dli` to RTI. With P=`$24`, HSCROL becomes **2**; with P=`$2C`, HSCROL becomes **12**. Both return with `boss_shown_pos = 14` and LMS=4, so the decimal case no longer satisfies `LMS*4 - HSCROL = position`. RTI correctly restores the original D flag.

**Why it matters / uncertainty.** An overlap with a BCD award can make the visible band disagree with collision coordinates. The unsafe arithmetic is confirmed. **Natural overlap with the second DLI on this exact ATR is a hypothesis, medium confidence:** I did not capture the interrupted PC on a fresh native replay. A timing or scoring change could expose it even if current normal paths avoid that overlap. The ordinary gameplay DLI also has an ADC at `src/main.s:3612`; its first-DLI scheduling needs separate reachability analysis before calling that a current fault.

**Smallest fix.** CLD at the boss DLI entry before arithmetic. RTI restores the interrupted P, so mainline BCD work can continue correctly. Re-measure the additional interrupt cycles and palette timing.

**Test that catches it.** Exercise all three DLI phases, positions 0..63, both D values, and nontrivial A/X/Y. Require identical display writes for D=0/1 and exact register/status restoration. The current phase-1 position-14 case fails.

### AUD-04 — the boss's 7,000-cycle stress check misses distinct-module kills

**What.** The stress fixture scans modules sequentially and points all five shots at the same column. Production scans all five slots and immediately processes every hit/kill, including each kill's column-map rebuild. The deferred draw queue does not bound that damage/rebuild work.

**Evidence.** `tests/boss-fortress.test.mjs:723-724`:

```js
const column = columnMap(memory).findIndex(/* one selected module */);
if (column >= 0) for (let slot = 0; slot < 5; slot += 1) shootAt(memory, column, slot);
```

The hard-coded order at `:717` also omits `plate-a`, `plate-b` and `plate-h`, although the test title says “every reachable module.” In production, `src/hybrid/boss.s:433-451` calls `boss_hit` for every qualifying slot; kills call `boss_rebuild_module` at `:603`.

**Reproduction.** The existing stress test passes at **6,689** cycles. Additional probes used its same accounting: `boss_update + boss_motion + three boss_dli NMIs`, from the linked region-1 entry at band position 32:

| Shots into distinct front modules, HP reduced to 1 in the copied fixture | Native instruction cycles |
| --- | ---: |
| Columns 30, 43, 50: plate-d, plate-g, plate-h | **7,343** |
| Columns 12, 30, 43: plate-a, plate-d, plate-g | **7,388** |
| Columns 12, 17, 21, 26, 30: five different modules | **10,745** |

For reproduction, copy `runBossEntry().memory`, `placeBand(memory,32)`, set `_boss_hp + boss_column_map[column]` to 1 for each target, call `shootAt(memory,column,slot)`, and apply the accounting above. These fixture states use legal front modules and pool slots. **An exact joystick/fire trajectory producing the simultaneous arrivals was not established.** Therefore this is S3, a confirmed gap in the stated stress bound, not a proven dropped frame in the ATR. These costs must not be compared directly to the DMA-on gate.

**Why it matters.** Sequential attacks on one target systematically avoid the repeated rebuilds that make multi-target frames expensive. Spread and previously launched shots make mixed-target arrivals worth testing; a one-module draw budget alone does not establish a whole-update budget.

**Smallest fix.** First expand the stress test to distinct modules, all reachable armour and stage/kill combinations. If native reachability confirms a budget violation, use a bounded per-frame destruction/rebuild allowance and defer remaining impacts while retaining their projectiles. Reuse the existing queue/state rather than redesigning the engine; verify damage and accuracy are still counted once.

**Test that catches it.** Assert the existing 7,000 limit on the three-target column-30/43/50 case, and add generated input traces to establish which mixed-target cases are naturally reachable. The synthetic three-target assertion fails today.

### AUD-05 — a new stale pin is hidden inside the accepted preview failure name

**What.** The failure registry says the preview test fails when changing the player shape does not change the image. It now fails earlier, on the obsolete gold palette value. The later player-shape, allied-colour and hull-source checks never run.

**Evidence.** `tests/preview.test.mjs:141` still expects:

```js
[0x00, 0x0e, 0x88, 0x1e, 0x46, 0x0e, 0x44, 0x44, 0x28]
```

`docs/recorded-test-failures.json:33-34` identifies `tests/preview.test.mjs:166` and the clipped player-shape defect as the first failure. The new player-side colour is `$AE`, recorded in STATUS and returned by the preview source reader.

**Reproduction.** Ran:

```sh
node --test --test-name-pattern='preview consumes the canonical charset|ten heaviest frames retain' tests/preview.test.mjs tests/runtime-wall-trace.test.mjs
```

The preview fails at **`:129`**, actual COLPF2=174 (`$AE`), expected 30 (`$1E`). I separately changed the first `player_shape` byte in an in-memory source string and called `createGameplayPreview`: the resulting buffers were equal. Thus the original known defect still exists, but the test no longer reaches it. The other recorded test fails at `tests/runtime-wall-trace.test.mjs:877` for the documented missing CPU reference; its cause remains correctly described, although its recorded line number is stale.

**Why it matters.** Tracking only failing test names cannot distinguish an accepted defect from a new earlier failure under the same name. This is the exact stale-pin-before-behaviour pattern highlighted in the audit brief.

**Smallest fix.** Update the legitimate colour expectation to `$AE`; split palette, shape, colour-source and hull-source checks into independently reported tests. Keep only the player-shape test recorded until its actual preview defect is fixed. Refresh the registry's locations.

**Test that catches it.** An independent palette test currently fails. Independent allied-colour and hull-source tests would execute even while the shape test remains recorded. A focused rerun should demonstrate the remaining failure is the documented behavioural assertion.

### AUD-06 — PAL audit PASS is weaker than the stated gates

**What.** `auditSession().passed` means “no distinct miss events,” not “all required budgets passed.” It permits a positive fence margin below 500 and hard-gate overruns that still fit the physical frame. The standalone CLI also reports success when it audits zero files, or skips invalid explicitly supplied CSVs.

**Evidence.** `scripts/pal-timing-audit.mjs:181-194` reports margin and hard overruns but ends with:

```js
passed: missEvents.length === 0,
```

At `:296-301`, CSV errors are caught and logged as `skipped`; the remaining audit set controls the exit code. The CLI does not require a nonempty audit set. The wall-trace harness calls this audit (`scripts/runtime-wall-trace.mjs:4662-4675`) and separately checks DMA-on limits, but does not enforce the 500-cycle margin through this predicate.

**Reproduction.** `node scripts/pal-timing-audit.mjs build` returned exit 0 and **“0 distinct miss events across 0 replays (PASS)”** in this fresh clone. A numeric one-row fixture with start scanline 18, `profile_clock19 = 240*114 - 100`, publication at `240*114 + 20`, and wall work 30,000 yielded `worst_fence_margin_cycles:100` and `passed:true`. The test at `tests/pal-timing-audit.test.mjs:92-93` even accepts a one-cycle margin as a caught fence; that establishes fence detection, not the project's GO budget.

**Why it matters.** A caller can mistake this PASS for compliance with the documented 500-cycle floor. An empty or malformed trace directory can provide a vacuous success. This does **not** establish that the current reported 1,472-cycle margin is wrong. Current distinct misses are detected and cause a nonzero wall-trace exit; that mechanism held up.

**Smallest fix.** Separate fence-catch detection from budget acceptance. Require the documented margin floor and hard limit in the acceptance predicate; label any detection-only result accordingly. Make zero valid replays and failed explicitly named inputs nonzero exits. Bind the acceptance result into the final evidence gate if the default build is meant to enforce it.

**Test that catches it.** Require margin 499 to fail and 500 to pass, while preserving the one-cycle fixture as a successful *fence catch*. Require a directory with no session CSVs and a malformed explicit CSV to exit nonzero. The current code fails these requirements.

## 4. Design concerns

The disk-safety mechanisms protect addresses within a known image more strongly than they protect media identity and stored content. AUD-01 and AUD-02 are separate consequences of that boundary. No filesystem loader or large rewrite is proposed: keep fixed runs and direct SIO, strengthen validation at the transition.

No defect is assigned to ATR-only distribution, PAL-only operation, `LEVEL_MAX_ID = 16`, the all-or-nothing Spread decision, character effects, the boss enemy ceilings, the accepted one-cell-late broadside hull-edge case, or the known preview/CPU-reference defects themselves.

## 6. Coverage and limits

### Coverage plan and actual reading

The initial plan prioritized four interaction boundaries: interrupt/mainline state, boss/pool lifecycle, boot versus transition disk loading, and tests/evidence exceptions. Runtime bounds and memory ownership were checked alongside those paths. Maintainability and unrelated presentation code received less attention.

**Read in depth:** sector-reader protocol, retry and validation paths; summary record read/update/write and arithmetic; the C boss controller; boss DLI/motion, shot handling, feedback ring, draw queue, column-map rebuild and install/restore; mainline frame order, player allocation/Spread admission and relevant BCD award paths; Director admission/sector transition and Light/Heavy deferral portions; generated map's active claims and corresponding cfg ranges; build C-runtime checks and artifact/evidence binding; PAL acceptance logic; selected boss, summary, reader, binding, observer and recorded-failure tests.

**Read/sketched for structure and followed relevant sections:** AGENTS/README/STATUS and documentation map, architecture/game design, the remainder of the memory map, roadmap §0 and budget plan, M5 decisions §1.6 and boss concepts, plasma/SPREAD/boot blanking/XEX reclaim plans, recorded-failure review/JSONs, hardware checklist, hybrid architecture, the rest of `main.s`, lifecycle/Director, Light kernel, build/level/boss converters, memory-map generator and wall-trace header/harness. These large files were not all read line by line. Only the current failure entries were checked deeply; the long registry of retired failures was sampled.

**Not exhaustively audited:** full music streams/POKEY mixing, every assembly branch and index, every level-converter field, all preview/capture utilities, all test files, every historical diagnostic, Windows/Intel host behaviour, every RESET/boot instruction, and the maximum nested hardware-stack call chain with arbitrary interrupt insertion.
